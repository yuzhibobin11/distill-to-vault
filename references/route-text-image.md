# 分支 A：图文（公众号 / 小红书 / 知乎 / 网页）

适用：有完整正文的网页类内容。目标是把「作者说了什么 + 凭什么这么说 + 我能拿它干什么」拆开。

## 1. 取全文

```bash
python scripts\fetch_text.py fetch "<url>"
```

产出 `content.md`，每段前缀 `[¶001]`。先看 `meta.json` 的 `char_count` 与 `degraded`。

| 情况 | 处理 |
|---|---|
| 成功，段数 ≥15 | 直接进入第 3 节 |
| `E_BLOCKED` | **不重试**。让用户在浏览器全选复制正文，粘贴给你；粘贴文本按空行重新编号 `[¶001]` 起 |
| `E_EMPTY` | 扫描件或纯图片页，同上转粘贴 |
| `degraded` 含 `no_ocr` | 小红书图文：正文只是配文，信息在图里。报告必须标 `coverage` ≤0.5 |
| 段数 <15 但字数正常 | 可能是长图式排版，检查 `content.md` 是否把整段切碎；可直接读原文人工分段 |

公众号专属坑：分享链有时效，`环境异常` 页会被当成正文（脚本已 guard）；图集类文章正文极短。

## 2. 定位方式

统一用 `[¶nnn "逐字引文"]`，编号来自 `content.md`。粘贴路径自己按空行编号，同样从 `¶001` 起。

**引文必填**：只有 `[¶012]` 没有引文的锚点会被校验器判 `QUOTE-MISSING` ERROR。引文 8-160 字，逐字照抄，可用 `…` 省略但片段须按序出现。

报告末尾必须有「定位表」，列出每个被引用的 `¶nnn` + 该段前 20 字。正文与定位表**双向核对**（`BIDIR` / `ORPHAN`），只列不引、只引不列都会报错。

## 3. 蒸馏维度（10 项，逐项过）

| # | 维度 | 抓什么 | 不合格的表现 |
|---|---|---|---|
| 1 | 主张清单 | 3-5 条，每条标 `断言 / 推测 / 转述` | 全是「作者认为很重要」这类空话 |
| 2 | 证据类型与强度 | 数据 / 案例 / 引用 / 类比 / 权威，标注强弱 | 把类比当证据 |
| 3 | 数据台账 | 数值、口径、时间、出处、定位，逐字照抄 | 把「增长 30%」写成「大幅增长」 |
| 4 | 论证链 | 前提 → 推理 → 结论，标出跳跃点 | 只抄结论，不写怎么来的 |
| 5 | 概念定义 | 作者自定义术语的原文定义 | 用常识理解替代作者定义 |
| 6 | 可执行清单 | 步骤 / 前置 / 成本 / 边界，四件套齐全 | 只有「要重视」没有动作 |
| 7 | 反常识点 | 与常识或主流说法冲突处 | 通篇复述共识 |
| 8 | 立场与利益相关 | 是否软广、带货、课程引流、雇主品牌 | 把软文当客观分析 |
| 9 | 时效性 | 数据年份、政策窗口、平台规则版本 | 拿三年前的数据指导今天 |
| 10 | 金句 | ≤3 条，每条 ≤50 字，带定位 | 大段摘抄原文 |

通过标准：1/3/4 三项必须有实质内容，缺任一项说明这篇不值得做成报告，直接告诉用户「这篇信息密度不足」。

## 4. 小红书专用两节

小红书的信息半衰期短，价值主要在结构与话术，不在论点深度。额外抽：

- **钩子结构**：前三行做了什么（提问 / 身份代入 / 数字 / 反差 / 痛点）；封面文字是什么（若能读到图注）。
- **商业目的判断**：有无购买链路、是否软广、评论区引导方向。结论写「商业内容 / 疑似商业内容 / 无明显商业目的」三档之一。

正文极短且信息在图上时，报告首行写「原文信息主要在图片，本次未做 OCR，`coverage` 按实际填写」。

## 5. 报告差异

用 `templates\report-base.md` 的骨架，不需要 delta。重点：

- 第 2 节「关键数据台账」是本分支的重头，宁少勿滥。
- 第 7 节「我的判断」必须与第 1 节严格分开，不能混。
- `coverage` 参考：正文完整且无图 → 0.9；缺图 → 0.6；缺关键段落 → 0.4。

## 6. 本分支的坑

1. **公众号 guard 误判**：正常文章也可能含「验证」二字。guard 只看前 6000 字符，命中即停；如确认是误判，让用户粘贴。
2. **知乎登录墙**：只拿到导语，后面全空。`meta.json` 的 `char_count` 会明显偏小，别硬写。
3. **小红书短链**：`xhslink.com` 需跟随 302，脚本已 `allow_redirects`；仍失败则让用户从 App 内复制全文。
4. **中英混排**：数字与单位之间的空格不要动，「1.2 亿」不能写成「120000000」。
5. **作者名缺失**：`author` 为空时写「未标注」，不要从正文猜。
