# 分支 C：论文与研报

适用：学术论文、券商研报、白皮书、招股书。目标是把「问题—方法—证据—边界」拆开，不是复述摘要。

## 1. 取全文

```bash
"C:/Users/李斌/.workbuddy/external-packages/pdf-cli/workbuddy-pdf.exe" \
  "<in.pdf>" "<out.md>" -f md-plain
```

PDF 路径可由环境变量 `WORKBUDDY_PDF` 覆盖。`md-plain` 自动做 OCR 检测，扫描件也能出文本。

**`md-plain` 输出自带 `<!-- page N -->` 页码注释**（实测 arXiv 15 页论文 → 15 个标记，位置准确）。所以 `[p.N]` 定位默认可用，用 `grep -n "<!-- page"` 先拿到页码锚点表即可，**不必**为了页码去跑 `-f split`。

**节级定位**：`md-plain` 会把章节标题抽成 markdown 标题（`# 3.2 Attention`）。`audit.py` 认这个，
所以 `[p.4 §3.2 "原文一句"]` 会精确取到该节正文（到下一个标题为止），比整页细一个数量级。
一页三千字挑不出支撑句，一节两三百字才行 —— **写锚点时优先用节，不要停在页**。
漏抽成标题的（`3.2.1 Scaled Dot-Product Attention` 单独一行）也能识别；
`§Abstract`、`§References` 这类无编号节按标题名定位。

需要逐页独立文件时（≤40 页，且 `md-plain` 页码注释缺失或错位）：

```bash
"<pdf-cli>" "<in.pdf>" "<pages_dir/>" -f split     # 每页一个 PDF
"<pdf-cli>" "<pages_dir/>/page-007.pdf" -f txt     # 逐页转 txt，得到 [p.7]
```

| 情况 | 处理 |
|---|---|
| `md-plain` 出文本且有 `<!-- page N -->` | 直接用，定位写 `[p.N §M.K "逐字引文"]`（默认情况） |
| `md-plain` 出文本但无页码注释，且 ≤40 页 | `-f split` 逐页兜底，得到 `[p.N]` |
| 无页码注释且 >40 页 | 不做逐页，用章节定位 `[§M.K ¶n]`，报告首行声明「页码不可用」 |
| OCR 结果乱码 | 让用户提供可复制版本，别硬读 |
| 网页版（arxiv abs / SSRN / 研报公众号转载） | 走分支 A 的 `fetch` |

## 2. 定位方式

`[p.7 §3.2 "逐字引文"]`：页码 + 章节 + **引文**。页码来自 `<!-- page N -->` 注释；拿不到页码时降级 `[§3.2 ¶n "引文"]` 并在报告首行声明。

三种特殊锚点：

| 情况 | 写法 | 校验行为 |
|---|---|---|
| 表格整表 | `[p.8 Table 2 "表内一行文字"]` | 引文须在该页逐字出现 |
| 表格单元格 | `[p.8 Table 2 r5c3]` | 无引文 → WARN，只当人工核对标记 |
| 公式 | `[p.4 eq.1]` | 无引文 → 要求正文出现 `unverified:formula`，否则 ERROR |

**注意**：`md-plain` 拉平表格会丢行列关系，所以单元格级永远无法自动验证。涉及关键数据的表格，必须回 PDF 原图核对，并把该数据标 `{M}` 或写进 `degraded: table-flattened`。

## 3. 学术论文维度（10 项）

| # | 维度 | 抓什么 | 不合格表现 |
|---|---|---|---|
| 1 | 研究问题 | 一句话说清在回答什么 | 「研究了 X 的影响因素」 |
| 2 | 方法与识别策略 | DID / 事件研究 / 回归 / 实验 / 案例，说明为什么可信 | 只写「用了回归」 |
| 3 | 数据与样本 | 样本量、期跨度、来源、清洗规则 | 漏掉样本期，结论无法判断时效 |
| 4 | 主要结论 | 含效应量与方向，禁写「显著提升」 | 只有形容词没有数字 |
| 5 | 机制 | 通过什么渠道起作用 | 相关性当因果 |
| 6 | 边界与稳健性 | 换了设定还成立吗，哪些子样本失效 | 只报主回归 |
| 7 | 作者自述局限 | 原文明确承认的缺陷 | 用你的批评替代作者自述，且不区分 |
| 8 | 文献增量 | 相对既有研究新在哪 | 把综述当结论 |
| 9 | 可复现性 | 数据可得性、代码、变量定义完整度 | 不写数据是否公开 |
| 10 | 利益冲突 | 资助方、数据提供方、作者 affiliation | 忽略行业资助 |

## 4. 券商研报额外 8 项

| # | 维度 | 抓什么 |
|---|---|---|
| 1 | 评级与目标价 | 买入/增持/中性，目标价，是否首次覆盖 |
| 2 | 盈利预测 | 营收、净利、增速，明确是哪一年、什么口径 |
| 3 | 估值方法 | PE / PB / DCF / SOTP，关键假设（增速、折现率、可比公司） |
| 4 | 核心逻辑 | 三条以内，能独立成立 |
| 5 | 催化剂 | 事件 + 时间窗 |
| 6 | 风险提示 | 原文列的 vs 你认为被低估的，分两栏 |
| 7 | 数据来源 | Wind / 公司公告 / 调研 / 专家访谈，标注哪些是未公开调研 |
| 8 | 合规 | 是否含免责声明、利益冲突披露 |

研报的核心风险是**把卖方观点当事实**。报告第 7 节「我的判断」必须回答：这份研报的立场是什么，它需要什么条件才成立。

## 5. 报告差异

用 `templates\report-delta-paper.md` 四段增量：

1. 文献信息卡（题目 / 作者 / 发表处 / 年份 / DOI / 类型）放第 0 节前。
2. 「方法与样本」放第 1 节前。
3. 「评级与预测」仅研报，放数据台账后。
4. 「局限与未证明」替换 base 第 6 节。

参考文献**不逐条罗列**，只留 ≤5 条必须回溯的关键文献（带 DOI）。

`coverage` 参考：全文可用 → 0.9；仅摘要+正文前几页 → 0.5；OCR 部分乱码 → 0.6 并在 `warnings` 说明。

## 6. 本分支的坑

1. **页码注释可能与图表占位符交错**：`<!-- page N -->` 与 `<!-- figure: ... -->` 混在一起，截取正文时别把 figure 注释当段落。定位前先 `grep -n "<!-- page"` 建锚点表。
2. **表格拉平成文本后列错位**：涉及关键数据的表格，回原 PDF 图核对，或直接用 `-f table` 单独导出。
3. **长研报（60-100 页）**：不要逐页 split，改用章节定位；否则耗时远超收益。
4. **公式与符号**：文本层常丢上下标，涉及公式的结论标「待核」，不要自行推导补全。
5. **同名不同版**：预印本与正式版结论可能不同，`published` 与 `DOI` 必须写清版本。
6. **中英混排的百分比**：`+12.3%` 与 `12.3 个百分点` 是两回事，逐字照抄。
